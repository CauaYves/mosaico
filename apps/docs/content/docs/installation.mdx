---
title: Instalação
description: Como adicionar componentes do Mosaico a uma aplicação.
---

Os componentes do Mosaico são distribuídos pelo registry do shadcn, servido direto do repositório [CauaYves/mosaico](https://github.com/CauaYves/mosaico). Cada componente instalado vira código do seu projeto.

## Requisitos

- React 19.2 ou superior;
- Tailwind CSS v4.

## Configure o projeto

Rode o `init` com a base do Mosaico, uma vez, na raiz do app:

```bash
npx shadcn@latest init CauaYves/mosaico/base
```

A base:

- grava o `components.json` com os ícones **Phosphor**;
- aplica o tema Multiclubes no CSS global;
- instala o utilitário `cn`;
- copia as regras do kit para `.claude/skills/mosaico-ui`, para o Claude usar os componentes do Mosaico em vez de recriar;
- copia o ciclo de protótipo para `.claude/skills/mosaico-prototipo`, para o Claude conferir cada tela por captura antes de mostrar.

Não use o `npx shadcn@latest init` sem a base: ele instala o `lucide-react` e cria o `Button` do shadcn oficial em `components/ui`, e o app começa com dois conjuntos de ícones e dois botões.

Para um app do zero, crie o projeto com o CLI do framework (`create-next-app`, `create vite`) e rode o `init` acima dentro dele. Os templates do `shadcn init` (`--template`) também criam o `Button` oficial.

## Instale um componente

```bash
npx shadcn@latest add CauaYves/mosaico/button
```

O comando copia o componente, instala as dependências npm e aplica o tema Multiclubes no CSS global. Componentes que dependem de outros (o `dialog` usa o `button`, por exemplo) trazem os dois.

## Onde os arquivos ficam

Os arquivos do Mosaico vão para pastas próprias, então convivem com componentes do shadcn oficial em `components/ui` durante uma migração:

| Tipo | Pasta |
| --- | --- |
| Componentes | `components/mosaico/` |
| Hooks | `hooks/mosaico/` |
| Utilitários | `lib/mosaico/` |

```tsx
import { Button } from "@/components/mosaico/button"

export default function Page() {
  return <Button>Salvar</Button>
}
```

## Tema e temas de cliente

O CSS global (`globals.css`) é do Mosaico: cada `add` reaplica as cores Multiclubes nele. Mudanças feitas direto nesse arquivo se perdem no próximo `add`.

Personalização de cliente fica num arquivo de tema separado, carregado depois do CSS global, só com as variáveis que mudam:

```css title="themes/cliente.css"
:root {
  --primary: oklch(0.55 0.22 25);
  --radius: 0.5rem;
}

.dark {
  --primary: oklch(0.65 0.2 25);
}
```

Esse arquivo sai pronto do [Create](/create): preencha o nome do cliente, escolha cor, raio e fontes, e use **Baixar tema** em **Usar este tema**. Salve o arquivo no projeto (no Portal, em `src/themes/<cliente>/`) e carregue-o depois do `globals.css`. Para ajustar o tema depois, abra o link `Editar:` do começo do arquivo ou arraste o arquivo para a página Create.

## Fonte

O tema usa a Geist (`--font-sans` e `--font-mono`), que o app carrega. Em Next.js, o `shadcn init` já configura; para fazer à mão:

```tsx title="app/layout.tsx"
import { Geist, Geist_Mono } from "next/font/google"

const geistSans = Geist({ subsets: ["latin"], variable: "--font-sans" })
const geistMono = Geist_Mono({ subsets: ["latin"], variable: "--font-mono" })

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="pt-BR" className={`${geistSans.variable} ${geistMono.variable}`}>
      <body>{children}</body>
    </html>
  )
}
```

Sem a Geist, os componentes funcionam com a fonte do sistema.

## Atualizar

Rodar o `add` de novo traz a versão mais recente do componente, a que está na `main` do repositório.

Componentes como `Tooltip` e `Toast` precisam de um provider na raiz da aplicação. A página de cada componente indica quando isso é necessário.
